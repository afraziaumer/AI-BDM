# Known Limitations

Current, honest limitations as of this handoff. Update an entry only when submitted code and test evidence prove the condition has changed — do not silently remove or soften an entry.

## RESOLVED — `wappalyzer==2.0.1` was not actually reproducible (discovered and fixed during this handoff)

The version pin `wappalyzer==2.0.1` in `requirements.txt` did **not** guarantee reproducible package contents. Confirmed live: a genuinely fresh `pip install -r requirements.txt` on 2026-08-06 installed a **different, incompatible build** under the exact same version string than what this development machine had installed (and had patched — see the entries below). That build has no `Wappalyzer.py` at all, a completely different internal module layout (`analyzers/`, `browser/`, `parsers/` instead of the old flat structure), and its `Wappalyzer` class exposes `analyze`/`analyze_many`/`close` instead of the `.latest()` classmethod `tech_stack.py`'s legacy engine depends on.

**Impact before the fix, confirmed live, not hypothetical**: `tech_stack.py`'s legacy detection engine (`_get_wappalyzer()`) raised `AttributeError: type object 'Wappalyzer' has no attribute 'latest'` on a fresh install — Stage 5 (tech-stack detection) did not work at all, regardless of the three encoding/regex patches below.

**Fix implemented (2026-08-06): vendoring.** `wappalyzer` is no longer pip-installed — it has been removed from `requirements.txt` entirely. A working, pre-patched copy of the package (all three patches below already applied) is committed directly into this repository at `vendor/wappalyzer/`, and `tech_stack.py` inserts `vendor/` at the front of `sys.path` at import time so `import wappalyzer` always resolves to the committed copy, never whatever PyPI happens to be serving that day. This makes the install fully reproducible regardless of future upstream PyPI changes. See `vendor/wappalyzer/README.md` for exactly what's vendored, why, and the procedure for updating the vendored copy in the future.

**Verified**: fresh venv, `pip install -r requirements.txt` (no `wappalyzer` package installed at all), full test suite (`pytest -q`) passes with zero manual post-install steps — including the 3 tests in `tests/unit/test_wappalyzer_patches.py` that previously failed on a fresh install. `scripts/patch_wappalyzer.py` is retained only as the one-time tool used to re-vendor a newer upstream release in the future, not as a required post-install step anymore.

| Area | Current disposition |
|---|---|
| Yelp / Trustpilot scraping | Bot-protection defeats even the premium (ScrapingBee) fetch tier's stealth mode. A production fix would require Yelp's official paid Places API — evaluated for cost, not implemented. |
| Dockwa (and similar JS-rendered review widgets) | Review text is populated client-side after page load; the scraper only sees the pre-render HTML shell, so extraction finds nothing even when the listing itself is correctly matched. Would need a JS-rendering fetch tier or a dedicated Apify actor for that specific platform. |
| Roman Urdu / code-switched review text | Statistical language detection (`langdetect`) cannot reliably distinguish Romanized Urdu from English, since it uses the same alphabet and often includes real English words — confirmed live: `"Sindh Balochistan ka idk k Kya criteria hota..."` detects as `"en"`. The review-relevance check can produce false flags on this kind of text. A real fix needs an LLM judgment call or multilingual sentence embeddings; neither is implemented. This is explicitly **not** required to be fixed as part of the non-LLM/current-system handoff. |
| ScrapingBee monthly quota | The development account's 1,000-call monthly quota has been exhausted multiple times during testing, silently degrading the premium fetch tier pipeline-wide (native-fetch-only) until the plan resets or is upgraded. This is a billing constraint, not a code defect — `_upload_with_retry`/premium-fetch error messages surface the exact `"Monthly API calls limit reached"` provider response when it happens. |
| Reddit official OAuth API | Abandoned after repeated recaptcha/redirect-URI friction during app registration. Apify's `trudax/reddit-scraper-lite` actor is the production path for Reddit mentions; the official API integration was never completed. |
| CRM-acronym fuzzy matching | `"customer relationship management"` does not fuzzy-match the literal token `"crm"` in the evidence-retrieval layer. Accepted, deliberate limitation — the project's design philosophy avoids hand-maintained synonym lists; each query's own keyword-expansion step (see `LLM_planner.py`) is expected to spell out realistic surface forms instead. |
| Third-party package patches (Wappalyzer, encoding/regex) | Three real bugs (BeautifulSoup parser, UTF-8 encoding, a broken Symfony fingerprint regex), all pre-applied to the committed copy at `vendor/wappalyzer/` — see the RESOLVED item above. No longer something a developer needs to apply by hand after install. |
| Network instability | DNS/network faults are treated as transient and retryable, never cached as a genuine no-result (see the transient-failure-vs-empty-result fix in `phase3/google_maps.py` and `phase3/review_harvester.py`). Real DNS instability was observed repeatedly on the development machine during this project's testing — unrelated to the codebase, but worth knowing if a "failure" doesn't reproduce on retry. |
| Cloudflare R2 sync | Implemented and tested against a real bucket (`storage_sync.py`) — whole-folder atomic sync, correct hierarchy preservation (a real Windows path-separator bug was found and fixed here), incremental skip via a per-domain manifest, and a `StorageProvider` abstraction so other backends can be added later. Optional — the pipeline runs identically with or without R2 credentials configured. |
| LLM dependency | The entire query-planning, routing-fallback, final-reasoning, clarification, and moderation layer is LLM-based (Groq). There is currently no non-LLM alternative implementation for any of these stages — see `docs/ARCHITECTURE.md` for exactly which stages require an LLM call and which run independently of one. |
| API wrapper (`api.py`) | Exposes only Steps 1–2 of the pipeline (`POST /pipeline/run`, plus read-only `/leads` endpoints). Steps 3–8 (routing, final reasoning, tech-stack detection, evidence retrieval, Maps enrichment, accuracy audit) are only reachable via the `main.py` CLI entry point today, not via this API. |
| Test suite | No automated test suite existed before this handoff pass. Now covers smoke (`tests/smoke/`), unit (`tests/unit/`), mocked-provider (`tests/mocked/`), and opt-in live-provider (`tests/integration/`, `pytest -m live`) layers — 62 offline/mocked tests plus 4 live tests, all passing. See `docs/HANDOFF_SUMMARY.md` for exact commands. |
